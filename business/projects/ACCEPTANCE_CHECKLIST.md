# Project acceptance checklist

Version 0.1 · Prepared 2026-10-13 · Proposed operating practice pending owner adoption

Project [[PROJECT_ID]] · Release [[DELIVERABLE_VERSION]] · Reviewer [[CLIENT_APPROVER]]

- [ ] Match each SOW criterion to a test/result and delivered version
- [ ] Supply review instructions and representative scenarios
- [ ] Test supported browsers/devices and agreed accessibility requirements
- [ ] Confirm permissions, error handling, integration retries and migration reconciliation
- [ ] Separate material defects, minor issues and enhancement requests
- [ ] Resolve material failures or document a specific client-approved exception
- [ ] Record known issues, severity, owner, workaround and due date
- [ ] Deliver agreed source/configuration/docs/training and license inventory
- [ ] Obtain explicit authorized acceptance under the agreement
- [ ] Retain exact evidence, date and approved version privately

Acceptance is separate from production launch. Do not infer acceptance from silence unless the reviewed executed contract expressly permits it and its notice/cure procedure has been followed. Launch still requires [launch checklist](LAUNCH_CHECKLIST.md).
