# Vendor access control

Version 0.1 · Prepared 2026-10-13 · Proposed operating practice pending owner adoption

Before a vendor receives access, complete vendor review and record service/data, purpose, scope, recipient organization, approved subprocessor/location, contractual security/privacy terms, duration and owner. Assess access separately from buying the tool.

- [ ] Verify vendor identity and official service URL
- [ ] Approve exact least-privilege role and data categories
- [ ] Use a named/time-limited account with MFA where supported
- [ ] Restrict production and client scope; no shared broad account
- [ ] Log actions where available and define incident/reporting route
- [ ] Prohibit unapproved secondary use or onward sharing in appropriate terms
- [ ] Record expiry and removal trigger; test export/exit path
- [ ] Review continued need quarterly and at contract/employee changes

Before renewal, recheck permissions, subprocessors, pricing, lock-in and deletion/export capability. A vendor's certification or marketing claim does not remove Noirdaz's duty to evaluate actual configuration and scope. Revoke access when the task ends and retain evidence without secrets.
