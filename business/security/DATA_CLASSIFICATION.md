# Data classification and retention

Version 0.1 · Prepared 2026-10-13 · Proposed operating practice pending owner adoption

Classify before intake. The highest-risk element controls the dataset unless it can be separated safely.

| Class | Examples | Handling |
|---|---|---|
| Public | Approved site copy, blank templates, public vendor docs | Publication still needs owner approval and rights check |
| Internal | Generic procedures, nonsensitive planning | Company access; review before external sharing |
| Confidential | Client contracts, business data, nonpublic financials, contact lists, employee records | Restricted private storage, encrypted transfer, named access, retention schedule |
| Restricted | Secrets, government IDs, health/minors data, card data, authentication and regulated datasets | Avoid collecting; specialized approved system and legal/security review before accepting |

No real client/employee/financial records belong in this public repository. Collect only the data needed for the agreed service; identify lawful purpose, client instruction, locations, subprocessors, retention and deletion owner. Do not use client production data for tests or AI/tool prompts without specific authorization and safeguards.

Maintain a private retention schedule by category: purpose, legal/contract basis, active retention, backup expiry, deletion method, legal-hold override and owner. A client's deletion request is routed to the owner and counsel where needed; verify authority and distinguish deletion from access/export rights. Record what was deleted, when, by whom, verification and valid retained exceptions. Do not promise universal privacy-law compliance from this classification scheme.
