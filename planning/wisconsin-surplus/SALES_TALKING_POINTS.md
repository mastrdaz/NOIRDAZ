# Wisconsin Surplus - Sales Talking Points

Use these as prompts. Do not read them word-for-word.

## 1. Warm opening
- Appreciated the call with their staff.
- Auction process was genuinely fun/exciting.
- Noticed one small point of friction during payment.
- Offer is about making that part easier, not criticizing the existing site.

## 2. Frame the problem
- Current winner email already contains almost everything the buyer needs.
- Standard card payments still require a phone call/email/manual step.
- Some exceptions clearly need staff involvement.
- Opportunity: separate routine payments from exception cases.

## 3. State the idea simply
- Add **Pay Online / Express Payment** to the existing winner email.
- Buyer opens a secure payment page.
- Invoice is identified automatically when possible.
- Buyer answers only the questions Wisconsin Surplus actually needs.
- Normal transaction -> secure hosted payment.
- Tax exempt / special case / high-value exception -> staff review.
- Phone option stays available for anyone who prefers it.

## 4. Preserve what already works
- Not proposing a replacement auction platform.
- Not proposing a giant site redesign.
- Keep their current simple, auction-first presentation.
- Add a small operational layer around payment.
- Start small and deepen integration only if useful.

## 5. Security boundary
- Prefer Wisconsin Surplus to own the payment-processor account.
- Prefer processor-hosted checkout.
- Noirdaz should not store raw card numbers/CVV.
- Keep auction/customer data in their existing system wherever possible.
- Portal should move references/status, not become a duplicate customer database.

## 6. Ask about current processor
Prompt:
- “What are you processing the phone card payments through now?”

Then:
- If it already has a good hosted checkout/API, use it.
- If not, Square is one option to demonstrate.
- Do not prescribe a processor before understanding their current setup.

## 7. Discovery transition
- “If you’re open to it, I only need a few questions answered to see whether this can be done cleanly.”

Priority questions:
- What generates the invoice/email?
- What processes phone cards?
- What cases require staff review?
- How does an invoice become marked paid?
- Does the auction platform have an API/export/import path?
- Rough payment volume?
- Would they prefer a limited pilot?

## 8. Explain Noirdaz
- Noirdaz Industries is a new, intentionally small client-facing business.
- You work full time in healthcare laboratory diagnostics.
- Software/systems have been your parallel technical field for years.
- You already build and operate working systems/sites.
- Now turning that into client work.
- They deal directly with you.
- No production change happens without their approval.

If directly asked about commercial client history:
- answer accurately
- do not inflate client count
- frame early-client status as direct access, flexibility, and a careful pilot process

## 9. Offer the demo
- Don’t ask them to buy an idea.
- Ask for enough workflow detail to build a test/demo.
- Use fake/redacted data.
- Show customer screens + staff outcome.
- Then provide:
  - rollout plan
  - fixed implementation quote
  - monthly managed-service price
  - responsibilities
  - support plan
  - optional future integration

## 10. Close
- “If it doesn’t clearly make the process easier, there’s no reason for you to change it.”
- Agree on next information they will provide.
- Agree on who reviews the demo.
- Do not ask for production credentials on the first call.

## Short version if the call is rushed
- Loved the auction process.
- Noticed routine payments still create manual calls.
- Could add a secure online-payment path without replacing the auction system.
- Keep exceptions/manual review intact.
- Use their existing processor if possible.
- Build a demo first.
- They approve every step before production.
